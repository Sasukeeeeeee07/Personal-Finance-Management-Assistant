# Deployment — personal use, ₹0/month

| Part | Host | Plan |
|---|---|---|
| Flutter web app | Vercel | Hobby (free, non-commercial) |
| NestJS API | Render | Free web service |
| PostgreSQL | Neon | Free |

Nothing here needs a card or a paid plan. **Do not upgrade any plan.** If a dashboard offers a paid add-on (Render
persistent disk, Neon paid compute, Vercel Pro), decline it; nothing in this app needs one.

Free-tier limits change. The numbers below were correct when written. Check each provider's pricing page before
relying on them.

> **Status:** these files and steps were prepared and checked locally (see "What was verified" at the end). Nothing has
> been deployed yet. Creating the accounts and pressing deploy is up to you.

## 0. What you need

- Accounts on GitHub, Neon, Render and Vercel (all free; signing in with GitHub is fine).
- This repository pushed to a GitHub repo you own (Render builds from Git).
- Locally: Flutter 3.35.x, Node 20+, and the Vercel CLI (`npm i -g vercel`). `pg_dump`/`psql` 16+ for backups.

Order matters: **Neon → Render → Vercel → back to Render for CORS.**

---

## 1. Neon (database)

1. Neon console → **New project**. Postgres **16**, region **AWS Asia Pacific (Singapore)**, which is closest to
   Render's Singapore region. Database name `pfm`.
2. **Connection details** → copy two strings:
   - **Pooled** (host contains `-pooler`): the app uses this one → Render's `DATABASE_URL`.
   - **Direct** (no `-pooler`): for `pg_dump`/`psql` backups only.
   Both must end with `?sslmode=require`.
3. Nothing else to run. The API creates the tables and reference data itself on first start. The database must
   be UTF-8, which is Neon's default; the API refuses to start otherwise.

Notes
- Neon suspends compute when idle. The first query after a pause takes a few seconds; the API's pool waits up to
  15 s for it.
- Render's health check uses `/api/v1/health`, which doesn't touch the database, so Neon can still suspend.
- Don't paste connection strings into chat, issues or commits. They contain the password.

---

## 2. Render (API)

1. Render → **New → Blueprint** → connect the GitHub repo. Render reads [`render.yaml`](../render.yaml): one free web
   service `pfm-api`, root `backend/`, region Singapore.
2. Render asks for the `sync: false` values:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | Neon **pooled** string, ending `?sslmode=require` |
   | `CORS_ORIGINS` | Your Vercel address, e.g. `https://pfm-yourname.vercel.app` (not known yet: put a placeholder `https://placeholder.invalid` and fix it in step 4) |
   | `APP_WEB_URL` | Same Vercel address |
   | `SMTP_*` | Leave empty unless you have an SMTP account (see "Email" below) |

   `JWT_ACCESS_SECRET` is generated by Render (`generateValue`). `NODE_ENV=production` and `TRUST_PROXY=1` are already set.
3. **Apply.** The build runs `npm ci --include=dev && npm run build`; the start command is `node dist/main.js`.
   On start the API applies pending migrations, serialized with a Postgres advisory lock so an overlapping
   deploy can't run them twice.
4. Check the API is up (replace with your Render URL):
   ```bash
   curl https://pfm-api.onrender.com/api/v1/health/ready
   ```
   Expect `{"status":"ok","database":"ok"}`. A `503 database_unavailable` means `DATABASE_URL` is wrong or Neon is unreachable.

If configuration is wrong, the API **refuses to start** and the Render log lists every problem, for example:
```
Invalid configuration:
- CORS_ORIGINS is required (e.g. https://your-app.vercel.app)
- APP_WEB_URL must be the https:// address of the web app (used in email links)
```
Production rules: JWT secret ≥ 32 chars; `DATABASE_URL` set; `CORS_ORIGINS` non-empty, `https://` only, no `*`;
`APP_WEB_URL` `https://`; `SMTP_FROM` required if `SMTP_HOST` is set. Swagger (`/api/docs`) is **off** in production
unless `ENABLE_API_DOCS=true`.

Free instance behavior
- It **sleeps after ~15 minutes without traffic**. The next request waits while it wakes, typically 30–60 s. The web
  app is built with a 75 s timeout for this (step 3). After that it's fast until it sleeps again.
- Free instances have no persistent disk. That's fine because all data lives in Neon.
- `autoDeploy` is off: deploy with **Manual Deploy → Deploy latest commit** when you choose to.

## 3. Vercel (web app)

Vercel's build machines don't have Flutter, so build locally and upload the finished files.

```bash
cd mobile
```
```bash
flutter build web --release --dart-define=API_BASE_URL=https://pfm-api.onrender.com/api/v1 --dart-define=API_TIMEOUT_SECONDS=75
```
```bash
vercel deploy build/web --prod
```

- The first `vercel deploy` asks you to log in and create a project. Choose a name (it becomes
  `https://<name>.vercel.app`) and accept the defaults. There's no framework and no build command, because the
  files are already built.
- [`mobile/web/vercel.json`](../mobile/web/vercel.json) is copied into `build/web` by Flutter. It sends every
  path to `index.html`, so refreshing `/accounts` or opening a reset-password link works. It also adds basic
  security headers and stops `index.html` / `main.dart.js` being cached, so updates show up on the next load.
- `API_BASE_URL` is the **only** value compiled into the app, and it's public by nature. Never pass secrets with
  `--dart-define`: anyone can read a web build.

## 4. Connect them (CORS)

Back in Render → `pfm-api` → **Environment**: set `CORS_ORIGINS` and `APP_WEB_URL` to the exact Vercel URL
(`https://<name>.vercel.app`, no trailing slash) → **Save** (Render redeploys).

Then open the Vercel URL, register, and add your first account.

Check from a terminal that only your site is allowed:
```bash
curl -s -D - -o /dev/null -H "Origin: https://<name>.vercel.app" https://pfm-api.onrender.com/api/v1/health | grep -i access-control-allow-origin
```
```bash
curl -s -D - -o /dev/null -H "Origin: https://example.com" https://pfm-api.onrender.com/api/v1/health | grep -i access-control || echo "blocked (correct)"
```

Vercel preview deployments get different URLs and will be blocked by CORS. That's intended. Use `--prod`.

## Email (optional)

Without SMTP the app works fully, but "forgot password" and "verify email" messages are **not sent**. In
production the API logs a warning without the link or token. To enable email, use any SMTP provider's free tier
and set `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` in Render. Delivery is retried
twice in the background, and recipient addresses are masked in logs.

## Updating

1. Run the checks locally (see `docs/TEST_REPORT.md`): `npm run lint && npm test` in `backend/`, and
   `flutter analyze && flutter test` in `mobile/`.
2. Push to GitHub → Render → **Manual Deploy → Deploy latest commit**. Migrations apply on start.
3. Rebuild and redeploy the web app (the two commands in step 3).

Deploy the API **before** the web app when a release changes the API. The web app tolerates an older API for
reads, but new screens need the new endpoints.

## Backups and restore

Neon keeps a short history you can restore from in its console (**Branches → Restore**). Its length on the free plan
is limited, so also keep your own dumps. Use the **direct** (non-pooler) connection string:

```bash
pg_dump "postgresql://USER:PASSWORD@ep-xxxx.ap-southeast-1.aws.neon.tech/pfm?sslmode=require" --format=custom --no-owner --file=pfm-$(date +%Y%m%d).dump
```

Restore into an **empty** database (a new Neon branch or project), never on top of live data:
```bash
pg_restore --no-owner --dbname="postgresql://USER:PASSWORD@NEW-HOST/pfm?sslmode=require" pfm-YYYYMMDD.dump
```
Then point Render's `DATABASE_URL` at it. The dump contains your financial data: keep it somewhere private and
encrypted, not in this repository.

## Rollback

- **API code:** Render → `pfm-api` → **Events** → pick the previous successful deploy → **Rollback**.
- **Web app:** Vercel → project → **Deployments** → previous one → **Promote to Production** (instant).
- **Database migration:** migrations are forward-only in normal use. `npm run migrate -- --down` exists for
  development and **destroys the data in the tables it drops**. In production, restore a backup to a new branch
  instead. Take a `pg_dump` before any release that adds a migration (listed in `docs/PROGRESS.md`).

## Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Web app: "The server is taking too long to respond" on first open | Render instance waking up. Retry after a minute. Rebuild with `API_TIMEOUT_SECONDS=75` if you left it out. |
| Web app: "You're offline" while online | Wrong `API_BASE_URL` (must be `https://…onrender.com/api/v1`) or a CORS rejection (see next row). |
| Browser console: CORS error | `CORS_ORIGINS` doesn't exactly match the Vercel URL (scheme, no trailing slash). |
| Render deploy fails at start, log shows `Invalid configuration` | Fix the variables it lists. |
| `/health/ready` → 503 | `DATABASE_URL` wrong, missing `sslmode=require`, or Neon project suspended/deleted. |
| Refreshing a page on Vercel gives 404 | `vercel.json` missing from `build/web`. Rebuild from `mobile/` so Flutter copies `web/vercel.json`. |
| Reset-password links point to localhost | `APP_WEB_URL` not set to the Vercel URL. |
| Want to force every device to sign in again | Render → Environment → regenerate `JWT_ACCESS_SECRET` invalidates access tokens only; to end sessions use Profile → "Sign out of all devices" (revokes refresh tokens). Don't rotate the secret routinely. |

## Security checklist

- [ ] No `.env` file committed (`git ls-files | grep -i "\.env"` shows only `backend/.env.example`).
- [ ] `CORS_ORIGINS` is exactly your Vercel URL; no `*`, no `http://`.
- [ ] Swagger off in production (`/api/docs` → 404) unless you deliberately enabled it.
- [ ] Neon password and dumps are kept out of chat, issues and Git.
- [ ] Every financial query is scoped to the signed-in user (enforced in the API and covered by tests).
